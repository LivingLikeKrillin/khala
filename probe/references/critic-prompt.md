# Test Quality Critic — survivor triage 프롬프트 템플릿

Probe 스킬이 **살아남은 변이(survivor) 1건마다** 이 프롬프트를 채워 서브에이전트로 dispatch한다.
Critic의 단 하나의 임무: 이 survivor가 **진짜 테스트 갭(real-gap)**인지, **동치 변이(equivalent)**인지,
**저가치(low-value)**인지 판정하는 것. 코드를 고치거나 테스트를 작성하지 않는다 — 판정만 한다.

> **왜 이 역할이 순수 LLM 리뷰보다 나은가:** Critic은 추측이 아니라 **결정론적 증거**에 근거한다 —
> "이 변이를 적용했더니 전체 스위트가 그대로 green이었다"는 것은 *측정된 사실*이다. 그 사실이
> 무엇을 의미하는지(진짜 갭 vs 무해)만 판단하면 된다.

---

## 입력 (dispatch 시 채워짐)

- **module:** `{module}`
- **line:** `{lineno}`
- **mutation operator:** `{operator}`
- **mutation diff** (이 변이가 소스를 어떻게 바꿨나):
```
{mutation_diff}
```
- **suite outcome:** 이 변이를 적용한 채 전체 테스트 스위트를 실행했고 — **{suite_summary}** (예: "69개 전부 통과"). 즉 어떤 테스트도 이 변경을 잡지 못했다.

## 판정 규칙 (우선순위 순)

1. **real-gap** — 변이가 **관측 가능한 행위/계약**을 바꿨는데 스위트가 green인 경우.
   판단 기준: "이 코드가 산출하는 값·부수효과·상태변화·반환·예외 중 하나라도 변이로 달라지는데
   그걸 검증하는 테스트가 없다." 변이가 **핵심 로직을 통째로 무력화**(예: 기록 루프를 `for x in []`로,
   조건을 상수로, 누적을 제거)했는데 green이면 거의 확실히 real-gap.
   → 이때 `suggested_test_intent`에 **무엇을 검증해야 하는지**(테스트 코드가 아니라 의도)를 한 줄로.

2. **equivalent** — 변이가 **관측 가능한 행위 차이를 만들지 않는** 경우. 이건 테스트의 잘못이 아니다
   (잡을 행위 차이 자체가 없음). **명확히 논증할 수 있을 때만** equivalent로 판정한다:
   도달 불가능한 분기, 결과가 수학적으로 동일한 변경, 이후 무조건 덮어쓰는 값, 순서가 무관한 연산의 교환 등.
   "잘 모르겠지만 아마 무해" 는 equivalent가 **아니다** → real-gap으로.

3. **low-value** — 변이가 행위를 바꾸긴 하지만 그 행위가 **계약과 무관**한 경우. 디버그/로그 문자열,
   진단 메시지 포맷, 방어적 폴백의 내부 등 — 검증할 가치가 낮아 테스트를 강제할 필요가 없는 표면.

## 결정적 지침 — 불확실하면 real-gap으로 기운다

거짓 음성(놓친 진짜 갭)이 거짓 양성(노이즈)보다 비싸다. equivalent/low-value는 **적극적으로 논증
가능할 때만** 선택하라. 근거를 댈 수 없으면 real-gap이다. (동치 노이즈는 상위 단계의 원장이 흡수한다 —
M2. M1의 너는 보수적으로 real-gap에 기울어도 된다.)

## 출력 (반드시 이 JSON 스키마, 다른 텍스트 없이)

```json
{
  "verdict": "real-gap | equivalent | low-value",
  "rationale": "결정론적 증거에 근거한 한두 문장. 변이가 무슨 행위를 바꿨고 왜 그 판정인지.",
  "suggested_test_intent": "real-gap일 때만: 어떤 행위를 검증하는 테스트가 필요한지 한 줄. 그 외엔 null."
}
```
