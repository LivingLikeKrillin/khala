# Khala 표준 기술 용어 사전 (Engineering Glossary)

본 문서는 Khala 생태계 전반의 아키텍처 문서, API 사양서, 다이어그램, 코드베이스에서 사용되는 핵심 공학 어휘의 정본(Single Source of Truth) 정의를 기술합니다. 

자의적인 번역, 구어체 및 의인화 비유를 배제하고, 결정론적이고 측정 가능한 산업용 소프트웨어 엔지니어링 표준 어휘 체계를 확립하여 시스템 전반의 용어 드리프트(Drift)를 방지합니다.

---

## 1. 용어 표기 및 선정 대원칙

1. **시스템/컴퓨팅 대상 용어는 원어 표기 및 업계 표준 음차 유지**
   - 시스템 내부 자료구조, 알고리즘, 모델 등 기계가 직접 처리하는 식별자는 영문 원어 또는 통용 음차를 사용합니다.
   - 예: `Chunk`(청크), `Vector Embedding`(벡터 임베딩), `Corpus`(코퍼스), `Tenant`(테넌트), `Token`(토큰), `RRF(Reciprocal Rank Fusion)`.
2. **평가 및 검증 영역은 확립된 통계학/공학 표준 한국어 적용**
   - 측정, 실험, 통계 검정 용어는 학술 및 산업 표준 한국어를 사용합니다.
   - 예: 대조군(Control Group), 실험군(Arm), 표본(Sample), 유의수준(Significance Level), 천장 효과(Ceiling Effect), 잡음 폭(Noise Floor).
3. **자의적 조어 및 의인화 은유 원천 배제**
   - 한국어 표준 대역어가 확립되지 않은 개념에 대해 자의적인 비유적 표현(예: 물리적 사물, 신체 부위, 주거 공간에 빗댄 표현)을 일절 배제하며, 확립된 영문 공학 용어를 그대로 사용하거나 명확한 기술적 서술어로 풀어냅니다.
   - 예: "~에 산다" → "~에 영속화된다 / 위치한다 / 격리된다", "~의 문이 있다" → "~용 엔드포인트 / 진입점 인터페이스를 제공한다".

## 2. 5대 핵심 도메인 용어 체계

### 2.1 도메인 및 지식 공정 (Knowledge Pipeline & Ingestion)

| 표준 기술 용어 | 영문 원어 | 기술적 정의 및 명세 | 배제/대체 표현 |
|---|---|---|---|
| **원천 문서** | Source Document | 시스템으로 수집되는 마크다운, PDF, 노션 페이지 등 불변의 원시 문서. | 원본 글, 대상 파일 |
| **청크 / 청킹** | Chunk / Chunking | 문맥 보존 단위(토큰 경계, 헤딩 계층)에 따라 분할된 원천 문서의 최소 색인 단위. | 조각, 글 토막 |
| **지식 코퍼스** | Knowledge Corpus | 특정 테넌트 또는 조직 도메인 하에 색인되어 검색 가능한 청크들의 논리적 집합체. | 지식 창고, 자료 더미 |
| **형태소 분석** | Morpheme Analysis | 한국어 어근/조사/어미를 분리하여 어휘적 정확도를 보장하는 어휘 분석 (`mecab-ko`). | 한국어 쪼개기 |
| **역색인** | Inverted Index | 형태소 및 키워드 기반 BM25 어휘 검색을 위해 구축된 전치 색인 구조. | 단어 사전, 키워드 표 |
| **벡터 임베딩** | Vector Embedding | 텍스트 청크의 의미적 맥락을 다차원 밀집 벡터로 변환하는 표현 기법 (`pgvector` 연계). | 의미 벡터, 좌표 변환 |
| **수집 파이프라인** | Ingestion Pipeline | 원천 문서의 파싱, 메타데이터 추출, 형태소 분석, 임베딩 생성 및 DB 저장을 수행하는 결정론적 데이터 공정. | 적재 흐름, 문서 넣기 |
| **색인 세대** | Index Generation | 임베딩 모델 또는 청킹 파라미터 변경 시 색인의 불변 정합성을 보장하는 버전 식별자. | 인덱스 판올림 |

### 2.2 인터페이스 계약 및 질의응답 (Interface Contracts & Answering)

| 표준 기술 용어 | 영문 원어 | 기술적 정의 및 명세 | 배제/대체 표현 |
|---|---|---|---|
| **하이브리드 검색** | Hybrid Retrieval | 키워드 역색인(BM25)과 의미 밀집 색인(Vector)을 병렬로 질의하는 다중 경로 검색. | 2갈래 검색, 양방향 검색 |
| **상호 순위 융합** | Reciprocal Rank Fusion (RRF) | 각 검색 경로의 순위 점수를 역순위 합산 공식(\(1/(k + rank)\))을 통해 단일 랭킹으로 통합하는 결정론적 알고리즘. | 순위 섞기, 랭킹 통합 |
| **근거 패킷** | Evidence Packet | 검색 랭킹 상위 청크에서 추출되어 LLM 답변 생성 컨텍스트로 주입되는 검증 가능한 증거 집합. | 증거 묶음, 참조 데이터 |
| **인용 검증** | Citation Verification | LLM이 생성한 인용 표기(`[S1]`, `[T1]`)가 실제 전달된 근거 패킷의 내용과 바이트 단위로 부합하는지 코드로 판정하는 게이트. | 출처 확인, 인용 검사 |
| **답변 수치 검증** | Numeric Grounding | 답변 본문에 포함된 수치(통계치, 식별자 등)가 근거 패킷 내 수치와 정확히 일치하는지 판정하는 정량 검증. | 숫자 대조 |
| **신뢰도 점수** | Confidence Score | 검색 융합 점수, 인용 완전성, 텔레메트리 일치성을 종합하여 답변의 보정 수준을 나타내는 정량 지표 (0.0 ~ 1.0). | 확신 정도, 품질 점수 |
| **기각 / 답변 거부** | Abstention | 근거 패킷이 불충분하거나 신뢰도가 임계치 미만일 때 허위 정보를 생성하지 않고 질의를 반려하는 동작. | 발뺌, 응답 포기 |
| **권위 창** | Authority Window | 비즈니스 불변식, 시스템 규약, 도메인 상수를 정적 코드 레벨에서 조회하여 보장하는 인터페이스 (`Archon`). | 진실의 창, 불변식 문 |

### 2.3 상태 머신 및 수명주기 관리 (State Machine & Lifecycle Governance)

| 표준 기술 용어 | 영문 원어 | 기술적 정의 및 명세 | 배제/대체 표현 |
|---|---|---|---|
| **영속화 / 저장** | Persisted / Stored | 데이터베이스나 불변 스토리지에 레코드 형태로 보관된 상태. | ~에 산다, ~에 머문다 |
| **승계 / 대체** | Supersede | 신규 유효 문서가 등록됨에 따라 이전 버전 문서를 비활성 상태로 전환하는 원자적 전이. | 덮어쓰기, 밀어내기 |
| **논리적 삭제** | Soft Delete | 물리적 행 삭제 대신 가시성 플래그를 비활성화하여 이력 추적성을 보존하는 상태 전이. | 지우기, 가리기 |
| **복원** | Revive | 논리적으로 비활성화된 문서를 동일 식별자 하에 다시 활성 검색 대상으로 복구하는 전이. | 살려내기, 되살리기 |
| **유효성 만료 / 드리프트** | Staleness / Drift | 기반 소스 코드의 변경 횟수 또는 시간 경과로 인해 문서 내용의 정합성이 훼손된 상태. | 낡음, 썩음 |
| **출처 등급** | Provenance Tier | 문서 및 텍스트의 생산 주체(인간 작성 `authored`, 비전 모델 판독 `machine_read` 등)를 식별하는 신뢰성 등급. | 족보, 신분 |

### 2.4 통신 및 신뢰성 프로토콜 (Inter-agent Communication & Protocols)

| 표준 기술 용어 | 영문 원어 | 기술적 정의 및 명세 | 배제/대체 표현 |
|---|---|---|---|
| **도구 간 프로토콜** | Agent-to-Agent (A2A) | Khala 생태계 내 자율 에이전트 간 정형 명세 및 작업 산출물을 교환하는 RPC/HTTP 통신 규약. | 에이전트 대화, 도구 연결 |
| **모델 컨텍스트 프로토콜** | Model Context Protocol (MCP) | LLM 실행 환경에 조직 지식 베이스(Nexus) 및 의사결정 도구(Arbiter)를 노출하는 표준 서버 인터페이스. | MCP 문, 에이전트 통로 |
| **인지 부채** | Cognitive Debt | 조직 내 시스템 복잡도 대비 실제 엔지니어가 명세와 코드를 이해하고 설명할 수 있는 역량 간의 결손 지표. | 뇌 부채, 이해 부족 |
| **보증 커버리지** | Vouch Coverage | Adept를 통해 책임자가 시스템 구성 요소 및 지식 항목에 대해 정량 평가를 통과한 비율. | 보증률, 점수 커버리지 |
| **변이 기반 테스트 하니스** | Mutation Test Harness | 소스코드의 구문을 체계적으로 변이(`Probe`)시켜 테스트 스위트의 결함 검출 능력을 엄밀히 측정하는 프레임워크. | 테스트 감시자, 변이 자 |

### 2.5 운영 거버넌스 및 감사 메커니즘 (Operational Governance & Audit Controls)

| 표준 기술 용어 | 영문 원어 | 기술적 정의 및 명세 | 배제/대체 표현 |
|---|---|---|---|
| **결정 원장** | Decision Ledger | 아키텍처 결정(ADR) 및 사양(SPEC)의 승인 이력, 승인자, 불변 본문 해시를 기록하는 추적 레코드. | 장부, 결정 목록 |
| **무결성 스탬프** | Integrity Stamp / Hash | 승인된 문서 본문의 공백 정규화 SHA-256 해시값으로, 사후 임의 수정 여부를 CI에서 결정론적으로 검증. | 도장, 해시 마크 |
| **검증 게이트** | Verification Gate | PR 병합 및 코드 생성 이전에 아키텍처 명세 준수, 테스트 통과, 문서 정합성을 강제하는 자동화 관문. | 안전망, 차단문 |
| **코드-문서 앵커** | Doc-to-Code Anchor | 문서가 서술하는 실제 소스코드 경로를 `doc-anchors.yml`에 매핑하여 코드 변경 시 문서 갱신을 추적하는 메커니즘. | 닻, 연결 고리 |
| **대조군** | Control Group | 평가 및 측정 시 외부 편향을 배제하기 위해 변경을 가하지 않은 기준 집합. | 비교군, 기준 팩 |
| **잡음 폭** | Noise Floor | 비결정론적 LLM 실행 또는 네트워크 지연에 의해 반복 측정 시 자연 발생하는 변동 구간(\(\Delta = \max - \min\)). | 잡음 바닥, 기본 노이즈 |
| **철회 공시** | Retraction Ledger | 사전 승인된 수치나 클레임이 측정 결함으로 판명되었을 때 이를 공식적으로 무효화하는 거버넌스 기록 (`specs/retractions.yaml`). | 취소표, 되돌림 |

## 3. 문서 작성 시 준수 규칙 (Engineering Style Guide)

1. **주어-술어의 명확성**: 능동형 명제 또는 명확한 시스템 주어를 기술합니다. 피동형 사변 표현("~에 대해 고려되어야 할 수 있다")을 금지합니다.
2. **단정적/측정적 서술**: 정량적 수치, 반환 타입, 에러 코드, 상태 전이 조건을 명시합니다.
3. **비유적 의인화 배제**: 시스템, 프로세스, 알고리즘을 사람이나 생명체로 묘사("~에게 물려받다", "~에 산다", "~가 화를 낸다", "~가 속인다")하지 않고, 객체지향적/기능적 관계("~를 상속/파생", "~에 영속화", "~예외를 발생", "~불일치 감지")로 기술합니다.
