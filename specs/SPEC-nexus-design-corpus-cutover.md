# Retire the copy and read the source — a gap is safer than an overlap

## 0. 무엇을 하는가

설계 문서 **사본을 정책 코퍼스에서 내리고**, `slack-bot` 이 정본 코퍼스를 **직접 읽게** 한다.
`SPEC-nexus-tenant-read-scope`(U1)가 넣은 기제의 자물쇠를 여는 SPEC 이다.

## 0.1 Backstop (ADR-0008)

```yaml
backstop:
- row: adr-0008-retrieval-stack
  reread: 2026-08-31 — 새 검색 채널·인덱스 백엔드·토크나이저/임베딩·커넥터 없음.
    바뀌는 것은 문서 수명주기 상태, principal 설정, 조각별 등급 판정, `search_log` 스키마다.
    ⚠ **재독 근거일 뿐 판정이 아니다.** 초판은 여기서 '검색 알고리즘은 그대로다 · 검색 경로
    변경 0' 이라고 **스스로 비적용을 논증**했는데, 같은 문서가 등급 판정을 검색 필터 경로에
    넣고 로그 스키마를 바꾸며 principal 하나가 두 코퍼스를 읽게 한다 — 어긋난다(I-006).
    ADR-0008 §3 은 게이트를 **director 가 선언하고 SPEC 은 기록만** 한다고 못박는다.
  clause: none
  ruling: does-not-fire
  ruled_by: LivingLikeKrillin
  ruled_at: '2026-08-31'
  recorded_note: |
    ⚠ 소유자가 대화에서 "서명한다" 고 말했고 **내가 이 칸을 채웠다.** 판정 내용은 위 재독
    근거(새 검색 채널·인덱스 백엔드·토크나이저/임베딩·커넥터 없음)에 따른다. 사람이 직접
    적은 것처럼 보이면 안 되므로 남긴다 — 아니라고 하면 되돌린다.
```

⛔ **이 판정이 채워지기 전에는 구현하지 않는다** (§6 P-1).

## 1. 실측 — 사본을 **정확히** 식별한다

⛔ **이 절의 초판에서 내가 숫자를 지어냈다.** 표의 *"정본 있음 115/115 · 6/6 · 1/1"* 은 질의
출력이 아니었다 — 그 질의는 `LEFT JOIN chunks` 로 행이 청크 단위로 불어난 뒤 세었으므로
실제 출력은 `1517 · 50 · 15` 였고, 나는 그것을 문서 수로 **읽어 옮겼다**. 비평(I-001)이 잡았다.
이 SPEC 은 같은 숫자를 두 번 틀렸다고 스스로 적어 놓고 **세 번째 계측기를 검증 없이 인용**했다.

다시 센다. 이번에는 **셋을 독립적으로** 확인한다.

### 1.1 술어

```sql
tenant = 'default' AND source_uri ~ '^default:(docs|modules|repo)/'
```

### 1.2 이 술어가 노션을 잡는가 — **배제하지 않고** 센다

```sql
SELECT CASE WHEN source_uri LIKE '%ext-notion%' THEN 'notion' ELSE 'not-notion' END,
       count(*) FROM documents
WHERE tenant='default' AND source_uri ~ '^default:(docs|modules|repo)/' GROUP BY 1;
--  not-notion 122   (notion 행은 **나오지 않는다**)
```

⚠ 초판은 노션을 그룹화 **전에** 제거해 놓고 *"노션은 안 걸린다"* 고 적었다 — 배제한 집합에
대해서는 원리적으로 아무것도 못 보인다(I-002). 위 질의는 배제하지 않는다.

### 1.3 정본이 있는가 — **제목에 기대지 않는다**

```sql
SELECT count(*) AS candidates,
  count(*) FILTER (WHERE EXISTS (SELECT 1 FROM documents e WHERE e.tenant='design_docs'
    AND substring(e.source_uri FROM 13)
        = regexp_replace(substring(d.source_uri FROM 9), '^docs/', ''))) AS by_path,
  count(*) FILTER (WHERE EXISTS (SELECT 1 FROM documents e WHERE e.tenant='design_docs'
    AND e.hash = d.hash AND e.hash <> '')) AS by_hash
FROM documents d
WHERE d.tenant='default' AND d.source_uri ~ '^default:(docs|modules|repo)/';
--  122 · 122 · 122
```

⚠ 초판은 제목 일치를 근거로 쓰면서 같은 문단에서 제목 일치를 기각했다 — 순환이었다(I-003).
**경로 대응과 내용 해시는 제목과 독립**이고, 셋이 같은 답을 준다. 122건 전부 정본이 있다.

| | |
|---|---|
| 사본 문서 | **122** (`docs/` 115 · `modules/` 6 · `repo/` 1) |
| 활성 청크 | **1,582** |
| 정본 대응 | 경로 122/122 · 해시 122/122 · 제목 122/122 |
| 노션 오탐 | **0** |
| khala 자기 문서(9종 113청크) | 술어에 **안 걸린다** |

## 2. 순서 — **겹치는 창을 만들지 않는다**

두 배치가 가능하다.

| | 창 동안 | 위험 |
|---|---|---|
| 부착 먼저 → 제거 | 정본·사본이 **함께** 온다 | ADR-0006 엔트로피 1위. 답변이 두 벌을 근거로 삼고 **아무도 못 본다** |
| **제거 먼저 → 부착** | 설계 문서가 **아무 데서도** 안 온다 | 답이 *"근거 없음"* 이 된다 |

⇒ **제거 먼저**를 고른다. **없는 답은 사람이 본다. 틀린 답은 안 보인다.**

창 길이는 **DB 갱신 ~ 재기동** 사이다. ⛔ **상한과 중단 기준을 정한다**(I-014): 재기동이 **10분 안에** 안 끝나면 §3 R-3 의 역연산으로 되돌린다. 그리고 K-3 가 *"부착하지 않는다"* 로 나오면 **제거를 시작하지 않는다** — P-2 가 선행이므로 순서상 그렇고, T1 측정도 K-3 판정 뒤다. 창 동안 설계 문서 질문이 답을
못 내는 것은 **의도된 것**이고, 그 사실을 배포 절차에 적는다.

⛔ 그래서 §5 의 대조는 **세 시점**(제거 전 · 제거 후 · 부착 후)이고, **제거 후 설계 라벨 셋이
떨어지는 것은 예상된 결과**다. 그것이 안 떨어지면 술어가 사본을 못 잡은 것이다.

## 3. 제거의 수단 — 그리고 **다시 들어오는 것을 막는 일**

### 3.1 supersede 는 안 쓴다

⛔ **교차 테넌트 supersession 은 오늘의 프리미티브로 표현이 불가능하다**:
`supersede(old_rid, new_rid, tenant)` 는 두 문서가 같은 테넌트에 있어야 한다.

**그리고 억지로 확장할 이유도 없다.** supersede 는 *"이 문서가 저 문서를 대체했다"* 는
관계이고, 여기서 일어난 일은 **같은 문서를 다른 테넌트에서 읽는다**는 것이다.

### 3.2 ✅ 수단이 **이미 있다** — 새 프리미티브를 안 만든다

초판은 `status='retired'` + `retire_reason` + `moved_to` 라는 **새 수명주기 프리미티브 둘**을
여기서 만들려 했다. 비평(I-009·I-016)이 *"근거가 없고 자리가 아니다"* 로 잡았고, 그래서
**찾아봤더니 있었다** (확인 2026-08-31).

| 있는 것 | 무엇 |
|---|---|
| `resource_status` enum | `active` · `superseded` · **`soft_deleted`** — 세 번째 값이 이미 있다 |
| `lifecycle.soft_delete` / `revive` | 대체 문서가 없는 소멸/부활. 상태 가드 있음 |
| `documents/lifecycle_ops.hide_document` | `soft_delete + hold=true` — *"사람이 이 문서는 검색에 있으면 안 된다고 결정했다"* |
| `restore_document` | `revive + hold=false` — **역연산** |

§3.1 의 네 요구가 그대로 만족된다.

| # | 요구 | 무엇이 만족하나 |
|---|---|---|
| R-1 | 검색에서 빠진다 | `status='soft_deleted'` — 오늘의 `status='active'` 필터가 막는다 |
| R-2 | 행은 남는다 | 상태만 바뀐다. 인용·피드백·`search_log` 의 rid 가 산다 |
| R-3 | 역연산이 있다 | `restore_document` |
| R-4 | 왜 내렸는지 남는다 | `hold=true` 가 **사람의 결정**임을 구별한다(재조정이 내린 것은 `hold=false`). 사유 본문은 이 SPEC 과 작업 기록이 갖는다 |

⭐ **덤으로 I-004 의 절반이 이미 닫혀 있다**: 재조정은 `hold = true` 인 문서를 **되살리지
않는다**(`notion_reconcile.py`). 사본이 재조정으로 조용히 돌아오는 경로는 막혀 있다.

⇒ **P-3(ADR 처분)가 필요 없다.** 만들 것이 없으므로 처분할 것도 없다. ⛔ 다만 §3.3 은 여전히
필요하다 — 재조정이 아니라 **적재 자체**가 같은 신원으로 upsert 하면 되살아난다.

### 3.3 ✅ 재적재도 이미 막혀 있다 — **검사로 박았다**

초판에 **이 조항이 없었다**(I-004). 다음 적재가 같은 신원으로 upsert 하면서 은퇴한 122문서를
되살리면, §2 가 피하려던 겹침이 배포 뒤에 조용히 재생성되고 어떤 완료 조건도 그걸 안 본다.

**확인 결과 (2026-08-31)**: 사본은 **파이프라인이 아니라 즉석 명령**으로 들어왔다(2026-08-30
적재). 끊을 상시 경로가 없다. 그리고 재적재 자체가 이미 막혀 있다 —

| | |
|---|---|
| 문서 | upsert 의 `ON CONFLICT DO UPDATE SET` 목록에 **`status` 가 없다.** 내용·제목은 갱신되고 상태는 그대로다 |
| 청크 | 저장 시 **부모 문서 상태를 따른다**(`_save_chunks`) — 부모가 non-active 면 청크도 안 산다 |
| 재조정 | `hold = true` 인 문서를 **되살리지 않는다** |

⛔ **읽어서 그렇다고 믿는 것과 검사로 박는 것은 다르다.** `test_document_lifecycle_db.py` 에
불변식 둘을 넣었다 — 숨긴 문서를 재적재해도 `status`·`hold` 가 그대로일 것(대조군: **내용은
갱신된다** — 적재가 죽은 게 아니다), 그리고 `hide → restore` 가 원상복구일 것. 실제 Postgres 에서
13개 통과.

### 3.4 엔트로피 신호 오염 (I-008)

사본은 정본과 내용·제목이 같으므로 `v_entropy_signals` 의 신호 ②(내용 해시 충돌)·③(제목 어간
충돌)이 **122쌍을 공존 후보로 센다**. 뷰가 `status` 를 거르는지 **확인하고 결과를 기록한다**
— 안 거르면 이 배포가 ADR-0006 이 Slice 2 방아쇠로 지정한 신호를 122건만큼 오염시킨다.

## 4. 조각별 등급 — **측정해 보니 만들 것이 없다**

U1 은 `len(read_tenants) > 1` 을 기동에서 막는다. 전역 `classification_level` 이
**principal 하나가 테넌트 하나만 읽는다**는 전제 위에 있기 때문이다.

⛔ 초판의 K-1 은 *"조각의 테넌트 어휘로 판정한다"* 였는데, 비평(I-005)이 **그것이 오늘
정의되지 않는다**고 잡았다 — enum 이 전역 하나뿐이라 *"테넌트 어휘"* 라는 것이 없다.

### 4.1 그래서 대조부터 했다 (2026-08-31)

```sql
SELECT tenant, classification, count(*) FROM documents
WHERE tenant IN ('default','design_docs') AND status='active' GROUP BY 1,2;
```

| 테넌트 | INTERNAL | RESTRICTED |
|---|---|---|
| `default` | 문서 246 · 청크 1,993 | 문서 2 · 청크 55 |
| `design_docs` | 문서 120 · 청크 1,527 | 문서 2 · 청크 55 |

**두 값뿐이고, 한쪽에만 나타나는 값이 없다.** 그리고 `RESTRICTED` 네 건을 열어 보니
**서로 사본이다**(같은 제목·경로 구조, 해시 대응).

### 4.2 결론 — 이 컷오버는 노출을 **안 바꾼다**

| | |
|---|---|
| 값 집합 | 두 테넌트 동일 (`INTERNAL`·`RESTRICTED`) |
| `RESTRICTED` 문서 | **같은 문서**의 정본과 사본 |
| `INTERNAL` principal 이 보게 되는 것 | 양쪽 다 `INTERNAL` 만. `RESTRICTED` 는 **어느 쪽에서도 못 본다** |

⇒ **조각별 판정을 만들 필요가 없다.** 어휘가 실제로 갈릴 때 — **두 번째 조직이 붙을 때** —
필요하고, 그때는 전역 enum 자체를 고치는 일이다(§7).

### 4.3 다만 자물쇠는 **없애지 않는다**

`MAX_READ_TENANTS_U1` 을 그냥 올리면 **앞으로 어느 쌍에든** 검사가 사라진다. 이번 쌍이
안전하다는 것은 **이번 쌍을 측정했기 때문**이지 일반 사실이 아니다.

⇒ 자물쇠를 **선언에 걸린 것**으로 바꾼다:

```yaml
principals:
  - name: "slack-bot"
    tenant: "default"
    read_tenants: ["default", "design_docs"]
    clearance_equivalence_verified: '2026-08-31'   # 없으면 기동 거부
```

| # | 불변식 |
|---|---|
| K-1 | `len(read_tenants) > 1` 인 principal 은 `clearance_equivalence_verified` 가 있어야 기동한다 |
| K-2 | 그 대조는 §4.1 의 질의이고 **결과를 SPEC 에 기록**한다 |
| K-3 | ⚠ 이것은 *"같은 뜻인가"* 의 **증명이 아니다** — 분포가 같아도 뜻은 다를 수 있다. 눈에 띄는 불일치를 잡는 회귀 검사이고, 그 한계를 여기 적어 둔다 |

## 5. 측정 — 사전 등록 (양방향)

### 5.1 술어 검증은 **답변이 아니라 잡힌 행**으로 (I-012)

⛔ 초판은 *"T1 에서 설계 라벨 셋이 안 떨어지면 술어가 사본을 못 잡은 것"* 이라고 적었다.
대안 설명을 못 배제한다 — 술어가 정확해도 남은 근거(자기 문서·노션)로 같은 라벨이 통과할 수
있고, 반대로 **과잉 삭제도 똑같이 라벨을 떨어뜨린다.**

⇒ 술어는 **§1.3 의 세 대조**(경로·해시·제목)와 **잡힌 rid 목록**으로 검증한다. 라벨은 술어의
증거가 아니라 **사용자가 받는 답의 회귀 검사**다.

### 5.2 대조 — 세 시점, **각 5회**

| 시점 | 기대 |
|---|---|
| T0 제거 전 | 기준선 |
| T1 제거 후 | 설계 라벨 셋이 떨어진다(예상된 결과, 배포 창) |
| T2 부착 후 | T0 로 돌아온다 |

**판정 규칙 (점수 보기 전에 박는다)**
- **세 시점 모두 5회씩** 돌린다. 초판은 T0 만 5회라 비교 통계량이 정의되지 않았다(I-010).
- 라벨별 통과율을 내고, **T0 에서 한 번이라도 흔들린 라벨은 판정에서 뺀다.**
- ⛔ **잔존 라벨이 12개 미만이면 부착을 보류한다**(I-011). 그 아래로는 비교가 공허하다.
- 비교 통계량: 잔존 라벨에서 **T2 통과율 = T0 통과율**(라벨별 전건 일치).
- ⛔ **양방향이다**(I-009). T2 가 T0 보다 **올라도** 원인 규명 전에는 채택하지 않는다 —
  상승은 §4 의 등급 과다노출이나 교차 테넌트 해소 누수가 원인일 수 있다.
- **되돌림**: 다르면 §3 R-3 의 역연산.

### 5.3 근거 점유율

질문당 **테넌트별 근거 조각 비율**을 기록한다. 값이 같아도 근거가 한쪽으로 쏠릴 수 있다.
첫 회차는 **관측**이고 임계는 그 분포를 보고 정한다.

### 5.4 로그 귀속

⛔ 교차 테넌트 조회를 principal 의 단일 tenant 로 기록하면 **`design_docs` 수요가 `default`
로 귀속되어** demand-pull 신호가 오염된다. `search_log` 에 **해소된 범위**를 남긴다.
칼럼·마이그레이션 번호는 구현 시 정하고 여기 기록한다.

### 5.5 ⛔ 이 작업을 당긴 수요 신호 (I-007)

ADR-0002 는 방향마다 **director 가 선언한 수요 신호**를 첫 SPEC 에 기록하라고 한다. 이 SPEC 은
그것을 비워 둔 채 §5.4 에서 신호 오염만 걱정했다. 채워야 할 칸:

```yaml
demand_signal:
  declared_by: LivingLikeKrillin
  declared_at: '2026-08-31'
  observation: |
    2026-08-30 소유자 지시 — "design_docs 을 슬랙에 붙여야 한다". 그리고 채널로 코퍼스를
    가르는 UX 를 기각하며 "어떤 질문을 하든 우리 넥서스에서 알아서 처리해야 한다" 고 했다.
    같은 날 "파일럿 목적 외에도 문서의 라이프사이클이 코퍼스에 반영되어야 하는 요구사항이
    존재한다" 고 못박아, 사본이 임시 타협이 아니라 닫아야 할 항목이 됐다.
  recorded_note: |
    ⚠ **내가 옮겨 적었다.** 위 관측은 대화 기록에서 가져온 소유자 발언이고, 선언 자체는
    2026-08-31 "서명한다" 이다. 아니라고 하면 되돌린다.
```

⚠ 내가 아는 사실만 적어 둔다 — 소유자가 *"design_docs 을 슬랙에 붙여야 한다"* 고 지시했고
(2026-08-30), 문서 생애주기 반영이 요구사항이라고 못박았다. **선언은 사람이 한다.**
