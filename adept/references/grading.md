# Adept 채점·피드백 규칙

채점 세션과 `adept review`(judge.py, service.remediate)가 따르는 규칙.
근거 등급은 [evidence.md](evidence.md) 참조. 채점 기둥은 아직 [가설] 위주 — 방어적 기본값으로 운용.

## 채점 (judge)

- **정답지 = 산출물.** 답을 산출물의 내용에 대조해 판정한다. 통과 기준은 **결정 + 이유의
  요지 일치**, 문구 재현이 아니다.
- **결정만 맞고 이유가 다르면 감점 통과**(score ≤ 0.6) 후 보완 학습 대상. 다른 논거는 다른
  상황에서 다른 결론을 낳는다. (첫 실전 루프 Q4 사례)
- **답의 길이·유창함을 평가에서 명시적으로 배제한다.** 짧고 정확한 답 > 길고 모호한 답.
  [가설 — LLM-judge 장황함 편향 방어]
- **fail-closed 유지**: LLM 오류·파싱 불가 = 실패. vouch는 벌어서 얻는 것. (judge.py 기존 원칙)
- "모르겠다"는 유효한 답 → `--failed` 정직 기록. 첫 실패는 정상 경로다. [검증 E1 — 실패해도
  인출 시도 자체가 학습]

## 오답 분류 (taxonomy)

rationale 앞에 코드 하나를 단다: `[코드] 설명…`. (2026-07-02 첫 실전 루프의 실측 유형에서 출발 — [가설])

| 코드 | 뜻 | 보완 학습 표적 |
|---|---|---|
| `not-retrieved` | 원칙은 알지만 판단에서 인출 안 됨 (재발형) | 상황→원칙 연결 재훈련; 본인 과거 결정과 연결 |
| `overgeneralized` | 배운 패턴을 엉뚱한 사례에 과일반화 | 두 사례의 구분 기준을 대조 설명 |
| `displaced` | 개인 신념/은유가 정본을 밀어냄 | 정본 문구와 그 확정 이유 제시 |
| `missing-rationale` | 결정은 맞고 이유가 없거나 다름 | 정본의 논거 제시 (결론 재확인 아님) |
| `no-knowledge` | 모름/백지 | 산출물 근거 기초 설명부터 |

같은 산출물에서 **여러 사람이 반복해 같은 코드로 틀리면 사람 아닌 문서의 부채** —
문서 개선 신호로 회송한다. [가설]

## 보완 학습 (remediate)

실패 직후, 산출물만 근거로: ①맞은 부분 인정 → ②정본의 결정과 논거 → ③이 지식이 실무에서
쓰이는 순간 하나. 설명형 피드백은 전이의 필요조건이다. [검증 E3] 길게 강의하지 않는다 —
다음 재시도(간격 사다리)가 학습을 완성한다.

## 지표 해석

- 커버리지·점수의 **사람 간 비교 금지**(g-혼입, rho≈.46) — 대시보드는 개인 랭킹이 아니라
  산출물별 고아/낡음과 동일인 추세를 보여준다. [검증 E8]
- 채점을 게이트로 쓰지 않는다 — 측정·표면화까지가 창구의 일. (ADR-0002 emission-only 경계)
