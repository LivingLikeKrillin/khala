# Nexus 외부 평가 — 평가 계획

작성 2026-09-02 · 평가자: 외부(Claude Opus 5) · 대상: **Nexus 한정**

> **이 문서는 실행 전에 동결된다.** 커밋 후 수정하지 않는다. 계획이 틀렸다는 것이 실행 중
> 드러나면, 계획을 고치는 대신 **그 사실을 결과 문서에 적는다.** 이 리포가 CI 로 강제하는
> 규칙("점수를 본 뒤 수정된 평가 하네스를 거부한다")을 평가자 자신에게도 적용한다.

---

## 1. 이 문서의 지위

내부 거버넌스 산출물이 **아니다.** SPEC 도 ADR 도 아니며 승인 게이트를 타지 않는다.
외부 평가자가 자기 방법을 미리 밝히는 문서이고, 짝이 되는 결과 문서
(`2026-09-02-nexus-external-evaluation-result.md`)와 함께 읽힌다.

**평가자의 이해충돌.** 이 계획을 쓴 자와 평가를 수행하는 자가 같다. 그것을 없앨 수 없으므로
두 장치로 묶는다 — §3 의 사전 지식 선언과 위의 동결 선언이다. 둘 다 없으면 이 문서는
평가가 아니라 연출이다.

## 2. 평가 대상과 고정

| 항목 | 값 |
|---|---|
| 대상 | `nexus/` 패키지 — 검색·근거 조립·답변 경로. Arbiter·Adept·Probe·Observer 는 범위 밖 |
| 코드 고정 | 실행 시점의 `git rev-parse HEAD` 를 결과에 기록 |
| 이미지 고정 | `docker compose images` 다이제스트를 결과에 기록 |
| 코퍼스 | 평가 전용 테넌트(§7). **라이브 `default` 코퍼스를 쓰지 않는다** — 재현 불가능하고, 다른 사람의 작업과 섞인다 |
| 임베딩 세대 | 실행 전 `nexus generation show` 로 선언 세대를 확인하고 기록 |

**모든 명령은 컨테이너 안에서 돈다.** 호스트 셸에서 돌리면 `config.yaml` 기본값 세대로
해석되어 검색되지 않는 컬럼에 적재된다(2026-08-10 사례). 실행 절차는 §7 에 고정한다.

## 3. 사전 지식 선언 — 평가 시작 전에 이미 알고 있는 것

**이 목록에 있는 것은 평가의 *발견*이 아니라 *확인*으로 분류한다.** 목록에 없는 것만 발견이다.
평가자는 2026-09-02 에 코드·문서를 읽었고, 그 과정에서 아래를 이미 알게 되었다.

| # | 이미 아는 사실 | 근거 |
|---|---|---|
| P1 | `repositories/graph.py` 가 `tenant = $2` 로 스칼라 바인딩하며 `tenant_predicate` 를 부르지 않는다. 답변 경로(`api.py`)는 `effective_read_scope` 의 **튜플**을 `hybrid_search` 에 넘기고, 그것이 `get_neighbors` 까지 전달된다. 실패는 `return_exceptions=True` 로 삼켜지고 `graph_search_partial_failed` 로만 남는다 | 코드 읽기 |
| P2 | `SearchResult.degraded` 에 실제로 들어가는 값은 `vector` 하나뿐이다. 그래프 다리는 죽어도 `degraded` 에 안 들어간다 | `grep degraded hybrid.py` |
| P3 | `/answer` 는 `effective_read_scope`, `/answer/stream` 은 `effective_scope` 를 쓴다. 스트리밍 경로는 다중 테넌트 읽기 범위와 `out_of_scope` 이벤트를 갖지 않는다 | 코드 읽기 |
| P4 | `search/hybrid.py` 의 모듈 docstring 이 여전히 `"BM25 + Vector + Graph 3-way 병렬 검색 + RRF Fusion"` 이다. `nexus/CLAUDE.md` 는 이것이 사실이 아니라고(그래프는 융합에 안 들어간다) 적고 있으며, 그 서술은 과거형이다 | 두 파일 대조 |
| P5 | `test_read_scope_reaches_every_enrichment.py` 는 기본 route(`hybrid_only`)로만 돌고 `graph_repo` 를 넘기지 않는다 | 테스트 읽기 |
| P6 | `confidence.py` 의 문턱(`FAR_DISTANCE=0.48`)은 표본 17건에서 나왔고, 중간 구간 최대값과의 여유가 0.010 이다 | 주석 |

P1·P2·P5 는 서로 물려 있으므로 층 0 이 이들을 **재확인**하도록 설계했다. 재확인 결과가
사전 지식과 다르면 그 차이 자체가 결과의 첫 줄이 된다.

## 4. 방법론 계약 — 이 리포의 규칙을 계승한다

새 방법론을 도입하지 않는다. `scripts/ko_eval_harness.py` 와 `scripts/ko_eval_answer_verdict.py`
가 이미 고정한 규칙을 그대로 쓴다.

| 규칙 | 출처 | 적용 |
|---|---|---|
| 답변 측정은 **팔당 3회 반복**, 질의별 3회 중 2회 이상이면 `ok` | `ko_eval_answer_verdict.py` | 층 3 |
| **잡음 폭을 먼저 보고한다.** 차이가 폭 이하이면 검정을 돌리지 않고 "회차 변동과 구별되지 않음" | 같음 | 층 3 |
| 양측 정확 이항검정(부호검정), α=0.05 | 같음 | 비교가 발생하는 모든 축 |
| **불일치쌍 6 미만이면 p 를 내지 않고 "검정력 부족"** | `MIN_DISCORDANT` | 같음 |
| 결론 못 내면 **현직 유지** | `ko_eval_answer_verdict.py` | 권고 작성 시 |
| 지표는 **다리별**로 낸다. 융합 숫자로 다리를 판정하지 않는다 | `ko_eval_harness.py` | 층 1 |
| 답변불가 라벨은 **분모를 섞지 않는다** | `AbstentionResult` | 층 3 |
| 채점기를 새로 쓰지 않는다 | `nexus/CLAUDE.md` | 전 층 |

**마지막 항목이 이 계획의 제약이다.** `ko_eval_answer_quality.py` 는 이미 있고, 2026-08-26 에
그것을 모르고 부분일치 채점기를 다시 써서 천장에 붙은 전례가 있다. 아래에서 "신규 계기"로
표시한 것만 새로 만들고, 나머지는 기존 스크립트를 호출한다.

## 5. 평가 항목과 척도

다섯 층으로 나눈다. **층 0 은 점수가 아니라 게이트**이고, 나머지 층의 숫자는 층 0 이 통과한
실행에서만 유효하다.

### 층 0 — 계기 무결성 (이진 게이트)

이 시스템이 반복해서 만든 결함은 "틀린 답"이 아니라 **"조용히 망가진 채 그럴듯한 답"** 이다.
`section_fill` 이 이틀간 전 요청에서 죽는 동안 검사는 전부 초록이었다. 그러므로
**한 번의 평가 실행은, 그 실행이 성한 시스템 위에서 돌았음이 증명될 때만 유효하다.**

| id | 항목 | 측정 | 통과 조건 |
|---|---|---|---|
| **L0-1** | 다리 생존 | 평가 질의 전체에 대해 응답의 `degraded` 수집 | 모든 질의에서 `degraded == []` |
| **L0-2** | 보강 생존 | 실행 중 앱 로그에서 `section_fill_failed` · `graph_search_partial_failed` · 짝 확장 실패 이벤트 계수 | **전부 0건** |
| **L0-3** | 보강 기여 | 질의별 `fill` 건수, `n_graph_edges`(그래프 route 질의만), 짝 확장 기여 건수 | 각 보강이 **최소 1건 이상**의 질의에 기여 |
| **L0-4** | 세대 일치 | `nexus generation show` 와 실제 적재 컬럼 대조 | 일치 |
| **L0-5** | 재현 정보 각인 | 결과 파일에 git rev · 이미지 다이제스트 · prompt sha · `labels_revision` · `llm_model` · 코퍼스 해시 · 세대 | 전부 존재 |

**위반 처리.** L0-1~L0-3 중 하나라도 위반이면 **그 실행의 층 1~3 숫자를 보고하지 않는다.**
대신 위반 자체를 결과의 1급 발견으로 기록한다. L0-4·L0-5 위반은 실행 중단 사유다.

> **이 게이트가 P1·P2·P5 를 재확인하는 장치다.** 사전 지식이 맞다면 그래프 route 질의에서
> L0-2 가 위반될 것이고, 그럼에도 `degraded` 는 비어 있어 **L0-1 은 통과할 것이다.**
> 그 조합(L0-2 위반 · L0-1 통과)이 관측되면 그것은 P2 의 실측 확인이다.

### 층 1 — 검색: 문서가 아니라 청크를 센다

기존 하네스는 **문서 단위 Recall@10** 으로 판정한다(`ko_eval_harness.py`, 청크를 문서로 접은 뒤
문서 10개 창). 그 선택에는 이유가 있고 유지한다. 다만 문서 단위가 가린 구간이 실제로 있었다 —
846자 권한 표가 앞 300자만 프롬프트로 가서 답이 불가능했는데 문서 Recall@10 은 1.000 이었다.

| id | 축 | 정의 | 계기 |
|---|---|---|---|
| **L1-1** | `doc_recall@10` · `MRR@10` | 기존 정의 그대로, 다리별 | 기존 (`ko_eval_retrieval_now.py`) |
| **L1-2** | `chunk_hit@10` | 정답 문서의 **어느 청크가** 창 안에 왔는가, 그리고 그것이 정답을 담은 청크인가 | **신규 계기** (라벨에 청크 정답이 없으면 사후 판정) |
| **L1-3** | `leg_rank` | 융합 **전** 각 다리에서 정답 청크의 순위 | 기존 다리별 지표 확장 |
| **L1-4** | `cutoff_margin` | 정답 청크의 다리별 순위와 `bm25_top_k`·`vector_top_k` 경계 사이 거리 | **신규 계기** |

**L1-4 를 넣는 이유.** 2026-08-26 에 정답 19자 행이 BM25 48위였고 `bm25_top_k`(20) 밖으로
밀려 융합에서 탈락했다. 그 상태는 탈락하기 **전날에도** 경계에 가까웠을 것이고, 여유를 재면
회귀가 터지기 전에 보인다. 이 축은 판정에 쓰지 않고 **관측만** 한다.

**판정.** 층 1 은 이번 평가에서 **기준선 수립이 목적**이다. 비교 대상(다른 팔)이 없으므로
합격/불합격을 내지 않는다. 예외: L1-1 이 커밋된 fixture 의 floor 를 밑돌면 회귀로 보고한다.

### 층 2 — 근거 조립: 프롬프트에 실제로 무엇이 갔는가

거의 측정되지 않는 층이고, 최악의 두 사고가 여기 살았다.

| id | 축 | 정의 | 계기 |
|---|---|---|---|
| **L2-1** | `evidence_completeness` | 정답 청크의 `chunk_text` 길이 대비, 프롬프트에 실제로 실린 길이의 비 | **신규 계기** — `assemble_packet` 산출물과 대조 |
| **L2-2** | `enrichment_contribution` | 질의별로 절 채움·짝 확장·그래프가 각각 근거에 더한 건수 | 기존 `fill` 필드 + **신규 집계** |
| **L2-3** | `provenance_tier_survival` | `machine_read` 근거를 포함한 질의에서, 등급이 프롬프트·인용·응답 표면까지 살아 도착하는가 | **신규 계기** — ADR-0010 의 hop 중 관측 가능한 것만 |

**L2-1 이 층 1 과 다른 것을 잰다.** 층 1 만점 + 층 2 낮음 = 846자 사례. 두 층을 나누지 않으면
그 구간이 존재하지 않는 것처럼 보인다.

**L2-3 의 범위 한정.** ADR-0010 은 여섯 hop 을 요구하지만, 이 평가는 **HTTP 응답과 프롬프트에서
관측 가능한 hop 만** 확인한다. MCP·웹 표면은 별도 실행이 필요하므로 범위 밖으로 두고, 그
사실을 결과에 적는다.

**판정.** L2-1 이 **1.0 미만인 질의가 하나라도 있으면** 그 목록을 보고한다(잘림은 이진 사건이
아니라 목록이다). L2-2 는 층 0 과 중복되는 관측이므로 판정하지 않는다. L2-3 은 위반 1건이라도
있으면 ADR-0010 §4 의 자기 기준("추출 안 하느니만 못하다")에 따라 결함으로 기록한다.

### 층 3 — 답변: 기존 축을 그대로 쓰고 둘만 더한다

`ko_eval_answer_quality.py` 가 이미 내는 축을 **새로 만들지 않는다**:
`grounded` · `cites_gold` · `facts_measurable` · `facts_present` · `all_three` ·
`outcomes{correct,incorrect,abstained,unadjudicated,unmeasurable}` · `refused` · `sufficiency` ·
`unverified_citations` · `no_citation_at_all`.

| id | 추가 축 | 정의 | 왜 |
|---|---|---|---|
| **L3-1** | `verifier_false_negative` | `unverified` 로 찍힌 인용을 사람이 재확인해, **표면 차이**(따옴표·분리자·접두)와 **실제 지어낸 출처**로 분리한 비율 | 지금 이 수는 코드 주석에만 있다(23건 중 대부분이 따옴표, 런당 5~8건이 분리자, 지어낸 출처 0건). 축이 아니면 `unverified_citations` 하락이 **모델 개선인지 검증기 수정인지 구별되지 않는다** |
| **L3-2** | `abstention_correctness` | 기권한 질의에 대해, 답이 코퍼스에 실재했는가 | 옳은 기권과 틀린 기권은 반대 방향의 사실인데 지금 `abstained` 하나로 세어진다 |

**L3-2 의 함정을 미리 적는다.** `confidence.py` 가 기록한 사례 — 부재 확인이 평가자의 어휘에
묶여 있어서, "코퍼스에 없다"고 지은 질문 6개 중 **둘은 코퍼스가 답을 갖고 있었다.**
따라서 L3-2 의 "실재했는가" 판정은 평가자의 검색어가 아니라 **키워드 다리 + 벡터 다리 양쪽에서
독립적으로** 찾은 뒤 사람이 확인한다. 이 절차를 안 지킨 판정은 무효로 적는다.

**판정.** 3회 반복 → 잡음 폭 먼저 → 비교가 있을 때만 부호검정(§4). 이번 평가는 단일 팔이므로
**절대값과 잡음 폭을 기준선으로 기록**하고, 합격선은 두지 않는다. 예외: `unverified_citations`
중 L3-1 로 분리한 **실제 지어낸 출처가 1건이라도 있으면** 결함으로 보고한다 — 그것은
"System decides, LLM narrates" 원칙의 직접 위반이다.

### 층 4 — 계기 자신

| id | 축 | 정의 |
|---|---|---|
| **L4-1** | `noise_band` | 같은 팔 3회의 `all_three` 최대−최소 |
| **L4-2** | `controls_fired` | 대조군 질의가 기대대로 거절되었는가 |
| **L4-3** | `margin_to_threshold` | `confidence.py` 문턱(0.48 / 1.5)과 이번 실행의 관측 분포 사이 여유 |
| **L4-4** | `adjudicator_note` | 사람 판정이 개입한 축(L3-1·L3-2)에서, 판정자 수와 불일치 건수 |

**L4-3 이 이번 평가에 있는 이유.** 문턱은 표본 17건에서 나왔고 중간 구간 여유가 0.010 이다.
주석이 *"실사용 질문 하나가 중간 구간에서 발동하면 그때 옮긴다"* 고 적었으므로, 이 평가가
그 트리거를 볼 수 있는 첫 외부 표본이다.

## 6. 라우트 층화 — 모든 층 1~3 지표에 적용

**집계 숫자만 보면 이 시스템의 결함은 보이지 않는다.** 그래프 다리가 죽어도 전체 평균은
거의 안 움직이고, `hybrid_then_graph` · `graph_then_hybrid` 에서만 `n_graph_edges` 가 0 으로
눌린다.

따라서 층 1~3 의 모든 지표를 `route_used` 별로 나눠 보고한다. 골든셋은
**세 route 가 모두 발동하도록** 구성한다(§7).

`determine_route` 의 발동 조건(엔티티 2개 이상, 또는 `의존성·호출·관계·연결·통신·아키텍처·
토폴로지·서비스 맵·불일치·차이·관측·실제` 키워드)은 IT 운영 질의에서 흔하므로, 라우트 층화
없이는 실사용의 상당 부분이 측정되지 않은 채 남는다.

## 7. 실행 절차

### 7.1 환경

```bash
task up                 # 6개 컨테이너 + 마이그레이션
task models             # 최초 1회
```

세대 확인 후 기록:

```bash
docker compose exec -T nexus-app nexus generation show
```

모든 평가 스크립트는 컨테이너 안에서 돈다:

```bash
docker compose exec -T nexus-app python -m scripts.<name>
```

### 7.2 코퍼스

평가 전용 테넌트를 쓴다. 기존 `ko_eval_packa` 계열 팩이 있으면 **그것을 재사용**하고,
없으면 커밋된 팩에서 적재한다. 라이브 `default` 는 쓰지 않는다.

코퍼스 해시와 문서 수를 결과에 기록한다.

### 7.3 골든셋 구성

기존 `tests/eval/ko/labels.yaml` · `answer-labels.yaml` 을 **정본으로 재사용**한다.
새로 라벨을 만들지 않는다 — 라벨 제작은 평가자가 아니라 팀의 일이고, 평가자가 만든 라벨로
평가하면 §3 의 이해충돌이 라벨까지 번진다.

다만 **라우트 커버리지가 부족하면** 기존 라벨 중 그래프 route 를 발동시키는 질의를
골라내어 층화 표본으로 쓴다. 부족하면 그 사실을 결과에 적고, 해당 층화 칸을
**"표본 없음"** 으로 남긴다 — 채우지 않는다.

### 7.4 실행 순서

1. 환경 기동 · 세대 확인 · 재현 정보 수집 (L0-4, L0-5)
2. 앱 로그 커서 기록 (L0-2 계수의 시작점)
3. 검색 측정 1회 (층 1) — 결정론이므로 반복 불필요
4. 답변 측정 3회 (층 3, §4 의 REPEATS=3)
5. 근거 조립 측정 (층 2) — 4번 실행의 산출물에서 추출
6. 로그 수집 · 층 0 게이트 판정
7. 사람 판정 축(L3-1, L3-2) 처리
8. 결과 문서 작성

**6번이 3~5번 뒤에 오는 것이 의도적이다.** 층 0 은 실행 중 축적된 로그로 판정하므로 사후이며,
게이트 위반이 나오면 **3~5번의 숫자를 보고하지 않는다.** 이미 얻은 숫자를 버리게 되더라도
그렇게 한다 — 그러지 않으면 게이트가 게이트가 아니다.

## 8. 결과 보고 형식

결과 문서는 다음 순서로 쓴다.

1. **재현 정보** — git rev, 이미지 다이제스트, 세대, 코퍼스 해시, prompt sha, `labels_revision`, `llm_model`
2. **층 0 게이트 판정** — 통과/위반. 위반이면 여기서 층 1~3 을 보고하지 않는 이유를 적는다
3. **확인 (P1~P6)** — 사전 지식이 실측으로 확인되었는가 · 반증되었는가
4. **발견** — 사전 지식에 없던 것만. 각 항목에 근거(파일·행·로그·수치)를 붙인다
5. **기준선** — 층 1~3 의 절대값과 잡음 폭, 라우트별 층화
6. **계기에 대한 관찰** — 층 4
7. **이 평가가 못 본 것** — §9 의 한계가 실제로 어디를 가렸는지

**판정 어휘.** "차이 없음"을 쓰지 않는다. 결론이 안 나면 **"검정력 부족"** 또는
**"측정하지 않음"** 이라고 쓴다. 안 본 것을 본 것처럼 적지 않는다.

## 9. 이 계획의 알려진 한계

- **평가자가 계획을 썼다.** §3 과 동결로 묶었을 뿐 없앨 수는 없다
- **단일 코퍼스·단일 실행.** 문턱과 분포는 코퍼스마다 다르다(`confidence.py` 가 명시)
- **비교 팔이 없다.** 이번 평가는 기준선 수립이고, 대부분의 축에서 합격선을 두지 않는다.
  합격/불합격을 내는 것은 층 0 게이트와, 원칙 위반이 명확한 두 경우(L2-3 위반, L3-1 의
  실제 지어낸 출처)뿐이다
- **LLM 비결정성.** 3회 반복으로 한 번 접지만 없애지 못한다
- **ADR-0010 의 6 hop 중 일부만 본다** (L2-3)
- **라이브 트래픽을 보지 않는다.** 평가 전용 코퍼스의 지어낸 질의이며, `confidence.py` 가
  기록한 "내 정규식이 못 찾은 것은 부재가 아니다"는 이 평가에도 그대로 적용된다
- **신규 계기 넷**(L1-2, L1-4, L2-1, L2-3)은 이 평가에서 처음 쓰인다. 계기 자신이 검증되지
  않았으므로, 그 축의 값은 **음성 대조**(고의로 깨뜨렸을 때 값이 움직이는지)를 함께 돌린
  경우에만 보고한다. 못 돌리면 "계기 미검증"으로 표시한다
