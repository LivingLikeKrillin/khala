# ken dogfood — 2026-06-23

First self-run of the cognitive-debt meter (`ken`) against khala's own critical
artifacts. The point of dogfooding: register the things that matter, measure how
many of them a *named human* can actually vouch for, and capture the honest
baseline. khala was largely AI-built; the expectation going in is that the
baseline is near-zero, and that is exactly what the meter should report.

## How it was run

The package is not installed; it lives in `ken/src`. On Windows the rich-rendered
help text contains an em-dash, which crashes under the default `cp949` console
codec, so UTF-8 must be forced. Commands were run from the **repo root** so that
the repo-root-relative artifact paths in the manifest resolve correctly, with the
manifest and ledger pointed explicitly at the `ken/` directory.

```bash
# from repo root: C:\Users\Eisen\Desktop\Labs\[projects] khala
export PYTHONUTF8=1 PYTHONIOENCODING=utf-8 PYTHONPATH="ken/src"

# register (idempotent on path; appends to the manifest)
python -m ken.cli register <repo-relative-path> --manifest ken/ken.manifest.yaml

# baseline coverage
python -m ken.cli coverage --manifest ken/ken.manifest.yaml --ledger ken/ken.ledger.jsonl
```

`python -m ken.cli --help` confirmed the three commands (`register`, `probe`,
`coverage`) before anything was registered.

## Friction notes

- The flow itself is clean: `register` → `coverage` is two commands and the
  orphan hotlist reads exactly like a debt ledger should. The 12-char path-hash
  ids are stable and survive re-registration, but they're opaque in the coverage
  output — you have to cross-reference the manifest to know *what* is orphaned. A
  `--verbose`/path-printing mode on `coverage` would remove the manual decode step.
- The Windows `cp949` em-dash crash on `--help` is the only real papercut. It's
  an environment/console issue rather than a code bug, but a first-time user on a
  Korean Windows box would hit a scary traceback before they ever see a command.
  Worth a note in the README (or forcing UTF-8 in the entrypoint).
- Path resolution is cwd-relative with no repo-root anchoring, so register and
  coverage must be run from the same directory. Easy to get right once known,
  easy to get subtly wrong (orphan-by-missing-file) otherwise. This is the main
  thing to weigh for the future hybrid-v1 decision: the meter is only honest if
  paths resolve identically at register time and at measure time.
