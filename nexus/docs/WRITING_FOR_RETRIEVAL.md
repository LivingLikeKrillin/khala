# 적재 친화 문서 작성 지침 — khala 가 잘 찾고 바르게 인용하는 문서의 모양

**누구를 위한 문서인가.** 새 프로젝트의 문서를 쓰는 사람과 에이전트. 문서가 khala 에 적재되어
검색되고 답의 근거로 인용될 것을 전제로 쓴다. 여기 적힌 규칙은 전부 **적재 코드가 실제로 하는
일**에서 나왔다(`ingest/chunker.py` · `ingest/classifier.py` · `ingest/title.py` · `config.yaml`,
2026-11-02 기준). 코드가 바뀌면 이 문서가 먼저 낡으므로, 규칙마다 어느 코드에서 왔는지 적어 두었다.

한 줄로 줄이면 **「검색 단위 = 운영 단위」** 다. 사람이 한 번에 읽고 한 번에 쓰는 덩어리가 청크 하나로
떨어지게 쓰면, 검색이 그 덩어리를 통째로 돌려주고 답이 그 덩어리를 그대로 인용한다. 2026-11-02 의
제조 도메인 조사에서 공개된 유일한 청킹 사고가 「절차가 단계 중간에서 잘려 미묘하게 틀린 답이
나온 것」이었고, 그 처방도 같았다.

---

## 1. 청크는 H1/H2 로 잘린다 — 절은 그 자체로 완결되게

`chunker._split_into_sections` 는 마크다운을 **H1 · H2 경계**로 자르고, 각 조각에 `H1 > H2` 형태의
section_path 를 붙인다. H3 이하는 경계가 아니다. 조각이 목표 길이(한국어 **1,100 토큰**, 영어 700,
`config.yaml chunking`)를 넘으면 문단 단위로 다시 나누되 **15% 오버랩**을 둔다.

그러므로:

- **한 H2 = 한 주제 = 한 질문에 대한 답.** 절차 하나, 결정 하나, 값 하나의 설명이 한 H2 안에 끝나게.
- **H2 제목은 혼자 읽혀야 한다.** 검색 결과와 인용 표시에 `문서 제목 > H2 제목` 이 그대로 나온다.
  「개요」「기타」「참고」같은 제목은 인용 표시에서 아무 정보도 주지 못한다. 「재적재 컨테이너는
  테넌트 하나만 본다」처럼 결론을 제목에 쓴다.
- **절차는 단계 목록을 한 H2 안에 전부** 둔다. 1,100 토큰을 넘길 것 같으면 절차를 나누지 말고
  설명을 줄여라. 넘치면 문단 경계에서 잘리고, 단계 7 과 8 사이가 잘리면 답은 7 까지만 안다.
- H3 로 소제목을 달아도 된다. 다만 **H3 는 청크 경계도, 인용 경로도 아니다.**
- 표는 한 H2 안에 완결되게. 표 머리와 본문이 다른 청크로 갈리면 열 이름 없는 숫자만 남는다.

## 2. 제목 — frontmatter `title` → 첫 H1 → 파일명

`title.derive_title` 의 우선순위가 그것이다. **frontmatter 에 `title` 을 적어라.** 없으면 첫 H1,
그것도 없으면 파일명(UUID 류)이 제목이 되어 인용이 「b7f3…」 로 보인다.

제목은 **답의 출처 표시**다. 「설계 노트」가 아니라 「검색 질의 텍스트 보존 — 옵트인·만료·철회」처럼
무엇을 결정했는지가 보이게 쓴다.

## 3. 문서 타입 — frontmatter `doc_type` 을 TTL 어휘로 적는다

분류기(`classifier._detect_doc_type`)는 frontmatter 의 `doc_type` 을 **먼저** 믿고, 없으면 **경로
키워드**로 추정한다.

| 경로에 들어 있는 말 | 추정 타입 |
|---|---|
| `api` · `contract` | `api_spec` |
| `spec` · `pipeline` | `spec` |
| `design` · `architecture` | `design_doc` |
| `policy` · `security` | `policy` |
| `config` | `config` |
| 그 외 | `markdown` |

신선도 경고(`documents/staleness.py`)는 **다른 어휘**를 쓴다 — `config.yaml staleness.ttl_days` 의 키
`ADR 365 · DESIGN 365 · RFC 365 · PRD 180 · RUNBOOK 90 · POSTMORTEM 180 · NOTE 730 · default 365`.
비교는 대문자로 하므로 `doc_type: runbook` 이라 적으면 `RUNBOOK` 의 90일이 적용된다. 경로 추정이
내는 `design_doc` · `api_spec` 은 어느 키에도 없어 **default 365** 로 떨어진다. 두 어휘가 다른 것은
알려진 결함이고(2026-11-02 평가 제안 5), 고쳐지기 전까지는 **작성자가 frontmatter 에 TTL 어휘로
적는 것이 유일한 제어 수단**이다.

```yaml
---
title: 재적재 컨테이너 운용 절차
doc_type: runbook        # ADR | DESIGN | RFC | PRD | RUNBOOK | POSTMORTEM | NOTE (대소문자 무관)
---
```

TTL 은 **적재 시각** 기준이다(원본 수정 시각을 쓰는 것은 제안 16 으로 열려 있다). 문서를 안 고쳐도
재적재되면 젊어진다 — 「낡지 않았다」가 「검토했다」는 뜻은 아니다. 검토한 날짜는 본문에 적어라.

## 4. 첫 문단에 결정 · 날짜 · 상태 — 답은 거기서 나온다

답변은 스니펫 몇 개로 만들어지고, 스니펫은 청크의 **앞부분**이다(`hybrid.py` 가 문장 경계에서
자른다). 그래서 H2 의 **첫 문단**이 그 절의 결론이어야 한다. 배경 → 논의 → 결론 순서로 쓰면 답에는
배경만 들어간다.

- **결정은 결정문으로.** 「검토 중이다」「고려할 수 있다」가 아니라 「2026-11-02, X 로 정했다. 이유는
  Y 다.」
- **날짜는 절대 날짜로.** 「지난주」「최근」은 적재되는 순간 뜻을 잃는다.
- **상태를 적어라.** 제안인지 결정인지 폐기인지. khala 는 상태를 추론하지 않는다 — 문서가 말하지
  않으면 답도 모른다.

## 5. 숫자와 값 — 단위와 조건을 같은 문장에

답에 나온 숫자는 `llm/numbers.py` 가 **근거 스니펫에 그 숫자가 실제로 있는지** 코드로 검사한다.
스니펫에 없는 숫자는 `unverified` 로 따로 보고된다. 그러므로:

- 값은 **문장 안에** 쓴다. 표에만 있으면 표 머리와 갈릴 때 검증이 깨진다.
- **단위와 조건을 붙인다.** 「1,100」이 아니라 「한국어 문서는 청크당 1,100 토큰을 목표로 한다」.
- 같은 값을 여러 곳에 적지 마라. 둘 중 하나가 낡는 날부터 답이 두 값을 나란히 내놓는다. 값은 한 곳에,
  나머지는 그 절을 가리킨다.
- 코드가 정본인 값(상수 · 설정 기본값)은 문서에 **의미**만 적고 숫자는 코드에 둔다 — khala 는 코드
  값을 `claim-value` 로 따로 읽어 문서 값과 나란히 낸다. 문서가 숫자를 들고 있으면 그 숫자가 틀리는
  순간 「문서 값 ≠ 코드 값」으로 잡힌다. 그것은 기능이지 오류가 아니다.

## 6. 문서를 바꿀 때 — 덮어쓰기 · 대체 · 이름 변경은 서로 다른 일이다

문서 식별자(`rid`)는 **`tenant:상대경로`** 에서 결정적으로 만들어진다. 그래서:

| 하는 일 | khala 가 보는 것 | 할 일 |
|---|---|---|
| 같은 파일을 고쳐 저장 | 같은 문서, 내용 해시가 달라져 **재적재** | 없음. 재적재가 알아서 한다 |
| 새 파일을 쓰고 옛 파일을 둠 | **두 문서가 공존**. 검색이 둘 다 돌려준다 | `nexus.cli supersede <old> <new> --tenant …` 로 선언. **자동 감지는 없다** |
| 파일 이름이나 경로를 바꿈 | **새 문서**가 생기고 옛 문서는 그대로 남음 | 하지 마라. 꼭 해야 하면 옛 경로를 `supersede` |
| 파일을 지움 | 삭제 감지 코드는 **Notion 경로의 `--reconcile` 에만** 있다(2026-11-02 확인 범위). 로컬 폴더에서 지운 파일은 적재된 채 남는다고 봐야 한다 | `nexus.cli doc` 으로 검색에서 내린다 |

대체 선언은 **사후 · 명시 · 멱등**이고 두 문서가 모두 적재돼 있어야 한다(`supersede.py`). 옛 문서는
지워지지 않고 `superseded` 상태로 검색에서만 빠진다. 되돌림은 `unsupersede` 다.

문서 머리에 「이 문서는 X 를 대체한다」고 **적는 것만으로는 아무 일도 일어나지 않는다.** 그 문장은
사람에게 하는 말이고, 검색에서 빼는 것은 선언 명령이다. 둘 다 하라.

## 7. 비밀과 개인정보 — 한 줄이 청크 하나를 격리시킨다

`config.yaml pii_patterns` 의 정규식(AWS 키 `AKIA…` · JWT `eyJ…` · 카드번호 · 주민등록번호)에 걸리는
청크는 **격리되어 색인되지 않는다**(`is_quarantined=true`, 기본 거부). 예시로 적은 가짜 토큰도 같은
운명이다 — 그 절 전체가 검색에서 사라진다. 예시가 필요하면 패턴에 안 걸리는 꼴(`AKIA` 뒤 16자
미만, `<redacted>`)로 쓴다.

비전 마커(`<!-- vision … -->` 류 기계 판독 표시)를 손으로 쓰지 마라. 적재는 마커를 **믿지 않지만
자르기는 한다**(`chunk_document` 의 `trust_vision_markers` 기본 False) — 산문이 엉뚱한 자리에서
갈린다.

## 8. 한국어 — 외래어는 두 표기를 한 번씩

BM25 는 mecab-ko 형태소, 벡터는 KURE-v1 이다. 평가셋(`tests/eval/ko/labels.yaml`)의 `loanword`
층이 측정하는 것이 바로 **「파드 / Pod」「앱아머 / AppArmor」처럼 한글 음차와 라틴 표기가 갈리는
경우**다. 문서가 한쪽만 쓰면 다른 쪽으로 묻는 질문은 못 찾는다.

- 처음 나올 때 **두 표기를 나란히** 쓴다: 「오토스케일러(HPA, Horizontal Pod Autoscaler)」. 그
  다음부터는 하나만.
- 식별자 · 명령 · 경로 · 설정 키는 **백틱**으로 감싼다. 토크나이저가 조사와 붙여 자르는 것을 막는다
  (`nexus-app` 을 「nexus-app 이」로 쓰면 `app이` 가 한 토큰이 된다).
- 프로젝트 고유 용어는 **한 문서에서 한 번 정의**하고 그 절을 가리킨다. 용어집 문서가 있으면 거기.
- 이 리포의 용어 규칙(`CONVENTIONS.md` §Terminology, `GLOSSARY.md`)은 적재 문서에도 적용된다.
  번역을 발명해야 할 것 같으면 원어를 써라.

## 9. 쓰지 말아야 할 것

- **답을 흉내 낸 FAQ.** 「Q: … A: …」를 문서에 넣으면 질문 문장이 그 질문의 검색을 독식하고 정작
  설명 절은 밀린다. 설명을 잘 쓰면 질문은 저절로 닿는다.
- **거대한 단일 H1 문서.** 섹션 경계가 없으면 1,100 토큰마다 기계적으로 잘리고, 모든 청크의
  인용 경로가 같은 제목이 된다.
- **본문을 그림에만 두는 것.** 그림 속 글은 기계 판독(`machine_read`)으로만 들어오고 출처 등급이
  낮다. 그림이 말하는 결론을 본문에도 한 문장으로 적어라.
- **다른 문서의 복사본.** 사본은 정본이 바뀌는 날부터 거짓말을 시작한다. 링크하라.

- [ ] H2 마다 첫 문단이 그 절의 결론이다
- [ ] 절차 · 표가 H2 하나 안에 끝난다
- [ ] 날짜는 절대 날짜, 상태(제안/결정/폐기)가 적혀 있다
- [ ] 숫자는 단위 · 조건과 같은 문장에 있고 한 곳에만 있다
- [ ] 외래어 첫 등장에 두 표기, 식별자는 백틱
- [ ] 가짜 토큰 · 카드번호 · 주민번호 꼴의 예시가 없다
- [ ] 이 문서가 대체하는 옛 문서가 있으면 `supersede` 선언을 같이 한다
- [ ] 파일 이름을 바꾸지 않았다
