# 도구 선택 층 — 드라이런 (호출 0회)

**묻는 것 하나:** *"이 질문에 어느 도구가 필요한가"* 를 **별도 분류기 없이 검색으로** 풀 수
있는가. 도구를 실제로 부르지는 않는다.

## 왜 이 형태인가

- 딥리서치(2026-08-15) 결론: 실시간은 **절대 임베딩하지 않고 답변 시점에 호출**한다. 대신
  *지도*(무엇을 답할 수 있는지)를 임베딩한다. 폐기된 것: **거대 정적 툴 카탈로그**.
- 이 리포는 *"모델에게 판정시키는"* 설계를 이미 한 번 기각했다
  (`SPEC-nexus-multi-turn-narration §3.2` — 오분류가 양방향으로 안전하지 않다).
  그래서 선택도 **검색**이어야 한다.
- 방아쇠는 이미 있다: `weak_evidence`(`nexus/search/confidence.py`) — *문서로는 답이 안 되는
  질문*을 시스템이 판정한다.

## 파이프라인 (측정 대상)

    질문 ─┬─ (A) default 검색      → 적합도
          └─ (B) 도구 지도 검색     → 적합도

    A 가 강하면            → 문서 (도구 미선택)
    A 약함 · B 강함        → B 의 1위 지도가 가리키는 도구
    A 약함 · B 약함        → 미선택 (지금의 "제가 아는 것은…" 카드)

적합도 판정은 배포와 **같은 코드**(`Confidence.weak`)를 쓴다. 자기 문턱을 따로 만들지 않는다.

## 판정 규칙 (측정 전에 박는다)

1. **오선택 1건이면 이 형태 그대로는 방아쇠로 못 쓴다.** 문서가 답하는 질문(`expect: docs`)에
   도구가 뜨는 것 — 오탐의 대가가 '군더더기 한 줄' 이 아니라 **외부 시스템 호출**이 되기 때문이다.
2. **미선택은 안전한 실패로 센다.** 도구 질문인데 아무것도 안 고른 것은 지금과 같은 카드가
   나가는 것뿐이다. 실패로 세되 차단 사유는 아니다.
3. **통과해도 "된다" 고 말하지 않는다.** 질문 13건 전부 저자가 지었다. 결론의 상한은
   *"이 형태로 더 갈 수 있다"* 이고, 진짜 눈금은 실사용 질문에서만 나온다.
4. 점수를 본 뒤 질문·기대값·문턱을 고치지 않는다.

## 한계 (미리 적는다)

- 도구 셋은 **아직 존재하지 않는다.** 지도는 선언일 뿐이고, 실행 층(MCP 클라이언트·인용·등급)은
  0줄이다. 이 실험은 **선택만** 잰다.
- 지도는 사람이 썼다 — 그래서 *"지도가 질문자의 어휘로 쓰였는가"* 도 같이 재진다(2026-08-18 에
  `ops-map` 이 `prod` 라 쓰고 질문은 `운영` 이라 해서 실패한 적이 있다).
- 실험 테넌트 `tool_probe` 는 라이브를 건드리지 않는다. `--drop` 으로 원상복구.

## 실행

    docker exec nexus-app python scripts/toolmap_probe.py --build   # 지도 적재
    docker exec nexus-app python scripts/toolmap_probe.py --run     # 판정 (LLM 0회)
    docker exec nexus-app python scripts/toolmap_probe.py --drop    # 되돌리기

## 1회차 결과 (2026-08-24) — 호출 0회 · 지출 0

**일치 9/13 · 오선택 0.** 사전등록 규칙 1(차단 사유)은 걸리지 않았다.

    도구 질문 6건   평균 벡터거리   문서팔 0.494 · 도구팔 0.379
    문서 질문 4건   평균 벡터거리   문서팔 0.429 · 도구팔 0.587
    코퍼스 밖 3건   양쪽 다 멂 → 미선택 3/3

**⚠ 1회차는 계측기가 틀려 있었다.** 첫 실행은 6/13 이었는데, 산출값이 도구 문서의 *제목*
(「지금 무엇이 떠 있나 — 배포 상태 조회」)이고 기대값은 *도구 이름*(`deploy-status`)이라
**같아질 수 없는 비교**였다. 신원을 파일명에서 읽게 고치고 다시 돌렸다 —
**문턱도 기대값도 질문도 건드리지 않았다.**

### 된 것

- **선택은 분류기 없이 된다.** 도구가 고려된 3건(t2·t5·t6)은 **전부 정확히 맞는 도구**를
  1위로 뽑았다. LLM 0회.
- **오선택 0.** 문서가 답하는 질문에 도구가 뜬 적이 없고(d1·d2·d4), 코퍼스 밖 3건은 양쪽 다
  약해서 미선택 — 지금의 카드가 나가는 자리다.

### 막힌 것 — 선택이 아니라 **방아쇠**

t1·t3·t4 는 도구를 **보지도 못했다**. 문서 다리가 *약하지 않다*(거리 0.460·0.475·0.459,
문턱 0.48)고 나와 순차 게이트에서 멈춘 것이다.

**왜 문서가 잘 맞았나 — 이게 이 실험의 핵심 발견이다.** *"지금 운영에 어떤 서비스가 떠
있어?"* 는 `ops-deploy-topology.md`(#296 이 만든 지도)와 잘 맞는다. 그 문서는 **설정이
말하는 의도**를 담고 있지 지금 상태를 모른다. 즉 **도구가 필요한 질문일수록 "그 주제를 다루는
문서" 는 존재한다.** 적합도는 *이 주제의 문서가 있는가* 를 재지 *그 문서가 지금 상태를 아는가*
를 재지 않는다 → **`weak_evidence` 단독은 도구 방아쇠로 부족하다.**

### 덤으로 나온 오탐 1건

d3(*"왜 서비스이름이 칼라인거지?"*)은 **코퍼스가 답을 갖고 있는데**(2026-08-24 적재) 문서
다리가 약함으로 찍혔다(d=0.559·b=1.0). 오늘 붙인 슬랙 한 줄이 **정답에도 붙는다**는 뜻이다.
지금은 대가가 한 줄이지만, 이 신호를 **호출 방아쇠로 승격하면 그 오탐이 외부 호출이 된다.**

### 다음 가설 (아직 결과 아님)

두 팔의 거리를 **비교**하면 도구 질문 6/6 이 도구팔 쪽이 가깝고 문서 질문 4/4 가 문서팔 쪽이
가깝다. 즉 *"문서가 약할 때만 도구를 본다"*(순차 게이트) 대신 **"둘 다 재고 더 잘 맞는 쪽"**
(비교)이 맞을 수 있다. ⛔ **이건 같은 데이터를 다시 읽은 것이라 결과가 아니다** — 새 질문
세트로 **사전등록하고 다시 재야** 한다.
