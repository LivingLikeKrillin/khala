# 도구 호출 실험 — 실제 도구(웹 검색)로, 실제 모델 판정으로

**묻는 것:** khala 의 시스템 프롬프트와 근거 패킷을 **다 본** 모델이, 옳은 순간에만 도구를
집는가. 그리고 도구 결과가 들어왔을 때 **인용 계약**이 어떻게 되는가.

## 왜 이 형태인가 — 앞의 두 회차와 무엇이 다른가

`tests/eval/toolmap/` 의 1·2회차는 **생성 이전**에 검색 점수만 보고 판정하는 라우터를 쟀고,
두 형태(순차 게이트·거리 비교) 모두 기각됐다. 업계 표준은 그 층을 만들지 않는다 — 도구 스키마를
요청에 실어 보내고 **모델이 생성 도중에** `tool_use` 로 결정한다(`tool_choice` 기본값 `auto`).

여기서는 그 표준 형태를 **실제로** 돌린다. 웹 검색은 서버측 도구라 MCP 클라이언트·수집기·메트릭이
0줄이어도 오늘 부를 수 있다 — 그래서 조직 실시간 데이터가 없어도 **기제**를 검증할 수 있다.

## 무엇이 검증되고, 무엇이 안 되나

| 검증된다 | 안 된다 |
|---|---|
| 트리거 — 모델이 언제 도구를 집는가 | 클라이언트측 루프(`stop_reason=tool_use` → 우리가 실행 → 되먹임). 웹 검색은 서버측이라 이 배관을 안 탄다 |
| 오탐 — 코퍼스가 답하는 질문에 도구로 새는가 | MCP 클라이언트·등급 대조(도구에 등급이 없다) |
| **인용 계약** — 웹 출처를 인용한 답변이 `validate_citations` 에서 어떻게 찍히는가 | 실행 층 SPEC 전체 |

## 프로덕션은 건드리지 않는다

이 실험은 **독립 스크립트**다. `providers/llm.py` 의 통제(*"요청에 tools 를 넣지 않는 것이 이
경로의 통제다"*)는 그대로 둔다. 검색·패킷 조립·프롬프트 조립은 **배포와 같은 코드**를 부르고,
API 호출만 스크립트가 직접 한다. 통제를 여는 코드 변경은 이 실험이 값을 하면 그때 SPEC 대상.

## 판정 규칙 (측정 전에 박는다)

1. **차단 사유: A군(코퍼스가 답한다)에서 검색이 발동하면** 이 형태 그대로는 못 쓴다.
   오탐의 대가가 외부 호출이기 때문이다 — 2회차와 같은 기준.
2. **C군(내부 상태를 묻는다)의 발동은 '무해한 오탐'으로 따로 센다.** 웹은 우리 조직 상태를
   모르므로 검색해도 답이 안 나온다. 비용은 들지만 답을 망치진 않는다 → 기록만, 차단 아님.
3. **B군 미발동은 안전한 실패.** 지금과 같은 답이 나갈 뿐이다.
4. 지출 상한 **$2**. 넘으면 그 자리에서 중단하고 거기까지를 결과로 쓴다.
5. 점수를 본 뒤 질문·기대값·규칙을 고치지 않는다.

## 한계 (미리 적는다)

- 질문 13건 전부 저자가 지었다. 실사용 질문이 아니다.
- 모델은 배포 기본값(`claude-sonnet-4-6`)을 쓴다 — 다른 모델은 다르게 집을 수 있다.
- 웹 검색은 유료다. 이 실험은 **지출이 있는 첫 실험**이고, 사용자 승인 아래 돌았다.

## 실행

    docker exec nexus-app python scripts/websearch_probe.py --limit 13

## 결과 (2026-08-25) — **브리지 경로로 돌렸다. 트리거를 정하는 것은 프롬프트 계약이었다**

Messages API 판은 계정 사용 한도로 막혔지만(2026-09-01), 호스트 `claude -p` 는
`--output-format stream-json` 이 `tool_use` 블록을 그대로 흘려주므로 **트리거를 관측할 수 있다.**
유료 키 없이 돌았다.

### ⭐ 발견 1 — 도구를 얹어도 안 부른다. 계약이 막고 있었다

A팔(계약 그대로) 10건 **전부 도구 호출 0건** — 날씨·주가·최신 버전까지. 계측기를 의심하고
프롬프트를 봤더니 이유가 그대로 적혀 있었다:

    1. **근거 기반 답변만**: 제공된 Evidence에 있는 정보만 사용하세요.
    5. **정보 부재 시 솔직하게**: 근거가 없으면 "…찾을 수 없습니다"라고 답하세요.

**모델은 옳게 행동했다.** 도구가 있어도 "제공된 근거만" 이라는 명시적 계약이 이긴다.

같은 질문·같은 근거 패킷·같은 도구로 조항 하나만 더한 B팔을 돌리자 갈렸다:

| | b1 (오늘 날씨) | b3 (최근 발표 모델) |
|---|---|---|
| A팔 — 계약 그대로 | 0건 | 0건 |
| B팔 — *"근거 밖 사실은 도구로 확인"* 1개 조항 추가 | **WebSearch 2건** | **WebSearch 3건** |

**즉 트리거는 라우터도, 모델의 변덕도 아니다 — 우리가 쓴 규칙 1번과 5번이다.**
도구를 붙이는 일은 배관이 아니라 **계약 변경**이고, 그래서 SPEC 대상이다.

부수 관측: B팔 답변은 조직 근거와 웹을 **스스로 구분**했다 — *"이 질문에 대한 내용은 검색된
조직 문서에 없습니다… 대신 웹으로 확인한 사실만 전합니다"* + `[출처: 웹, URL]`. 서술 계약은
살아남았다.

### ⭐ 발견 2 — 웹 출처 인용은 **전부 미검증으로 찍힌다**

| 질의 | 인용 | 미검증 |
|---|---:|---:|
| b1 | 1 | **1** |
| b3 | 4 | **4** |

`validate_citations` 는 **패킷의 문서 제목**과 대조한다. 웹 출처는 패킷에 없으니 100% 미검증이다.
그 수는 `search_log.unverified_citations` 와 웹 배지로 흘러가므로, **옳게 출처를 밝힌 답변이
모든 표면에서 가장 못 믿을 답변으로 보인다.** 추상적으로 "SPEC 대상" 이라고만 적었던 문제의
실물이다.

### 충실도 한계 (결과와 같이 읽어라)

- Claude Code 의 자체 시스템 프롬프트가 살아 있고 khala 프롬프트는 그 위에 덧붙는다.
- 허용목록을 `WebSearch` 로 줘도 `ToolSearch`·`WebFetch` 가 돈다 — 도구 표면이 배포보다 넓다.
- A팔 10건은 **답변 본문을 잃었다**(아래). 도구 호출 수는 표준출력에 남아 있다.

### 소비와 사고

하니스 보고 기준 **약 $4.05**(API 청구 아님). 그중 **$3.16 은 버렸다** — 상한 도달 메시지가
cp949 콘솔에서 `UnicodeEncodeError` 로 죽었고, 저장이 루프 **끝**에 한 번뿐이라 답변 10건이
사라졌다. 고쳤다: 출력 인코딩 고정 + **매 건 저장**.
